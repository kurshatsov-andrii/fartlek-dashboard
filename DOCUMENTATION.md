# Документація: Fartlek Events 2026

Зведений опис архітектури та недавніх змін (карта, глибокі посилання на події, сторінка події, UX). Базовий запуск і стек див. у [README.md](./README.md).

## Маршрути та посилання

| Що | Куди |
|----|------|
| Головна з фокусом на список подій | `/#events` |
| Список подій, відфільтрований за містом | `/?city=<URL-encoded назва>#events` — будується через `eventsSectionHrefForCity()` у `src/lib/events-deep-link.ts` |
| Сторінка однієї події (аналітика, афіша, кнопки) | `/event/[slug]` — `sportEventPagePath()` у `src/lib/event-detail.ts`; slug латиницею (`eventSlugFromTitle` + `src/lib/cyrillic-transliterate.ts`) |
| Абсолютний URL для шарингу | `sportEventAbsoluteUrl()` з `FARTLEK_SITE_ORIGIN` у `event-detail.ts` |

## Секція подій (`src/components/sections/events-section.tsx`)

- Обгортка **`Suspense`** навколо контенту, що використовує `useSearchParams`, щоб уникнути проблем з гідратацією на клієнті.
- Внутрішній компонент **`EventsSectionContent`** читає query-параметр **`city`** і в **`useEffect`** виставляє фільтр міста в стані (`setFilters`). Після переходу з мапи користувач бачить вже відфільтрований грід.
- **Важливо:** рядок міста в URL має **точно збігатися** з полем `city` у `SportEvent` (кирилиця тощо), інакше фільтр не знайде подій.

## Карта (`src/components/sections/map-section.tsx`)

- **Праворуч:** кнопки фільтрації (наприклад upcoming / finished), **прокручуваний список подій** з посиланням **«Детальніше»** на `/event/[slug]`.
- **Поведінка панелі:** не скидати вибір міста при `mouseleave` з крапки на мапі — панель не «стрибає» без потреби.
- **Розумний дефолт фільтра:** за замовчуванням upcoming, якщо є майбутні події для вибраного міста; інакше — finished.
- **«Усі міста»** скидає вибір, повертає загальний топ регіонів.
- **Крапки на мапі:** при наведенні на крапку логіка `hovered` лишається — оновлюється панель деталей по місту.
- **Блок «Топ регіонів» (список міст):**
  - наведення на **рядок списку** **не** змінює `hovered` і **не** перемикає панель на це місто (немає «перескакування» при hover по списку);
  - бейдж **`N подій`** — **кнопка**: відкриває в цій же панелі список подій міста з **«Детальніше»** (виставляє `hovered` для міста; без переходу на головну). Пряме посилання `/?city=…#events` лишається в `eventsSectionHrefForCity` за потреби з інших місць.

## Інші UX-зміни (коротко)

- **Картки подій:** один CTA **«Детальніше»** замість окремих «Реєстрація / Результати»; порядок рядків: перегляди, потім дистанції; підписи дистанцій без «дист.» і без зайвих ком; дистанції відсортовані за спаданням; повні назви організаторів; монограма організатора — **дві латинські літери** (`organizerLatinInitials`, спільна транслітерація).
- **Hero:** основний CTA узгоджений з картками — **«Детальніше»**.
- **Топ організаторів:** замість зображень — **дволітерні латинські монограми**.
- **Адмін «Останні додані події»:** сортування за часом **Telegram-поста** (`telegramPostDate` на `SportEvent`, виставляється в пайплайні `sport-events-from-telegram.ts`).
- **Сторінка `/event/[slug]`:** повноширинний hero-зображення; блок **«Текст афіші»** з очищенням URL (`stripUrlsFromAfficheText` у `src/lib/affiche-text.ts`); посилання в Telegram перенесені в коректне місце (без дубля під CTA).
- **Календар:** у переліку подій за днем — **«Детальніше»** як `Link` на `sportEventPagePath`.

## Перевірка після змін

```bash
npm run lint
npm run build
```

Вручну: з мапи натиснути **«N подій»** у топі регіонів → має відкритись `/?city=…#events`, прокрутка до блоку подій і коректний вибір міста у фільтрах.

## Примітки

- Підпис бейджа на мапі навмисно узагальнений як **`N подій`** (без склоніння 1/2/5 для стислості в UI).
- Якщо `npm run build` колись падає з рідкісними внутрішніми помилками Next (наприклад, згадки `/_error`), варто повторити збірку та звірити версію Next — не обов’язково це регресія з логіки карти/подій.
